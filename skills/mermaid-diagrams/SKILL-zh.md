# 生成 Wiki 页面中的 Mermaid 图表

图表是高质量 wiki 生成的一部分，不是装饰。当流程、
生命周期或数据模型更容易通过视觉理解时，在
最相关页面的 fenced ```mermaid 块中嵌入 Mermaid 图表。

## 选择图表类型

- `sequenceDiagram` 用于跨组件的运行时和请求流程（认证流程、请求生命周期、代理工具循环）。
- `stateDiagram-v2` 用于生命周期和状态机（作业状态、连接状态、运行阶段）。
- `erDiagram` 用于数据模型：实体及其关系。
- `flowchart TD` 用于分支控制流和决策逻辑。

## 纪律

- 每个图表都基于检查的源码。不要编造代码不支持的参与者、状态、实体或关系。
- 覆盖高价值场景：在页面文档化请求或运行时流程、调用序列、生命周期或状态机、或数据模型的地方添加图表。仓库 wiki 通常有几个这样的图表，而非一个整体的。跳过导航、参考表或纯配置的页面。
- 仍然优先几个强有力的图表而非装饰每个页面：一个准确图表在需要它的页面上胜过强制放在每个页面上的图表。
- 在每个图表正下方给出一行标题说明它展示什么。
- OpenWiki 在你运行后验证每个 mermaid 代码块，并将解析失败的代码块转换为普通 text 代码块。降级的图表是质量失败；请遵循以下语法规则以避免这种情况。

## 语法安全

这些规则防止最常见的渲染损坏。如有疑问，请重新表述标签。

- 绝不在节点、消息或边标签中放置分号或竖线。
- 绝不在标签中放置未转义的角度括号；写 "returns Promise of User" 而非 "returns Promise<User>"。
- 在 `flowchart` 中，将包含括号、方括号或其他标点的标签用双引号包裹：`A["calls foo(bar)"]`。
- 在 `flowchart` 中，绝不使用裸单词 `end` 作为节点 id，绝不让节点 id 以 `o` 或 `x` 加连字符开头（两者都是边标记语法）；重命名该节点。
- 在 `sequenceDiagram` 中，带空格或标点的参与者名称需要别名：`participant AS as Auth Service`。
- 绝不使用 Mermaid 保留字作为参与者名称、别名或节点 id：`note`、`end`、`loop`、`alt`、`opt`、`par`、`and`、`else`、`activate`、`deactivate`、`class`、`state`、`click`、`link`。例如通知参与者必须是 `Notifier`，而非 `Note`（与 `note` 关键字冲突）。
- 在 `erDiagram` 中，实体和属性名称必须是单个标识符式 token；将人类措辞放在关系标签中。
- 保持标签简短。将解释移到周围文字或标题中，而非图表中。

## 更新运行

- 错误的图表是过时声明，而非需要保留的现有结构。如果源码变更使图表不准确，在与周围文字相同的编辑中更新图表。
- 不要重写仍然准确的图表。重新生成未更改的图表会产生 diff 噪声。
- 如果页面包含前面有以 "openwiki: mermaid parse failed" 开头的 HTML 注释的 text 代码块，那是之前运行降级的图表。使用注释中的解析器错误修复语法，恢复 ```mermaid 代码块，并删除注释。
